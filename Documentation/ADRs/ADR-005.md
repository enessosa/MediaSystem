# ADR-005: Auth: start with sessions, move to JWT later

## Status

Accepted

## Date

08.08.2026

## Context

Someone logs in, and every request after that HTTP forgets who they are. So I need a way to keep that identity around. a Server-Side session would be enough for this App, but i also want to learn more complex tools, which is why im first going to implement Server-Side Sessions, but will migrate over to JWT after that.

## Decision

I'll do it in two steps. First a normal server-side session login (`HttpSession`
via Spring Security) so I have working auth quickly. Later I'll rebuild it on JWT

## Alternatives Considered

- **Jump straight to JWT** 
- **Just stick with sessions**: enough for the scale, but then I never touch the token side, which is the main thing I wanted to learn.
- **Token in `localStorage`**: Any injected script can read it (XSS).

## Consequences

**Positive:**

- Auth works early, and I get real hands-on with Spring Security, tokens and
  revocation

**Negative / Trade-offs:**

- I'm basically building auth twice, and the refresh-token table needs a bit of cleanup logic that a pure session wouldn't.
