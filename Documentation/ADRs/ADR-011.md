# ADR-011: Accounts Without Email Address

## Status

Accepted

## Date

24.10.2026

## Context

Registration required a username and an email address, and login accepted either of them. The email address was
never used for anything else: MediaSystem sends no emails, so there is no confirmation mail and no "forgot password"
flow. Since ADR-007, every instance is run privately for a small group of people who know each other, which makes
email-based features even less likely. Storing the address was a personal data point without a purpose, and it was one
more required field during registration.

## Decision

Accounts consist of username and password only. The `email` column is dropped from `app_user` with a new Flyway
migration, and login works by username only. Registration, the account page and the API responses (`RegisterResponse`,
`MeResponse`) no longer contain an email address. The login request keeps its field name `identifier` so the API
contract stays the same.

## Alternatives Considered

- **Option A:** Keep email as a required field: no change needed, but it stores personal data without any use.
- **Option B:** Make email optional: keeps the door open for future email features, but adds a nullable column,
  validation for an optional field and UI for something nobody uses.
- **Option C:** Use email for password reset: the only feature that would justify it, but it needs an SMTP server and
  credentials on every private instance, which is too much setup for a self-hosted app.

## Consequences

**Positive:**

- Less personal data stored (data minimisation), less to protect and to delete
- Simpler registration with one field fewer
- Less code: no email uniqueness check, no `EmailAlreadyExistsException`, no lookup by email

**Negative / Trade-offs:**

- The migration deletes all stored email addresses on existing instances; this cannot be undone
- A forgotten password still cannot be recovered by the user; a password reset by the admin would be the fitting
  solution for private instances
- Should email features ever be needed, the column and the registration field have to be added again
