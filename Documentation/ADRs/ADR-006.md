# ADR-006: UI Component Library

## Status

Accepted

## Date

19.10.2026

## Context

The official frontend (Phase 4) needs a consistent, accessible UI: forms, dialogs, menus, navigation,
pagination, banners, light and dark mode. I had never written React/TypeScript before this phase, and the
focus should stay on React itself and on the connection to the backend, not on building and styling every
component from scratch. The look I wanted was close to GitHub's interface.

## Decision

Primer React (`@primer/react`), GitHub's own design system, is used as the component library. Layout details
that Primer doesn't cover are written as CSS Modules using Primer's design tokens (CSS variables), so colors
and spacing stay consistent and work in light and dark mode automatically.

## Alternatives Considered

- **Option A:** Own CSS only: full control and good practice for CSS, but every dialog, menu and
  form control would have to be built and made accessible by hand. Too much effort next to learning React.
- **Option B:** Tailwind CSS: fast styling, but still no ready-made components (dialogs, menus, focus
  handling), and the GitHub look would have to be recreated manually.
- **Option C:** A general-purpose library (e.g. MUI): complete and widely used, but its Material look
  is far from the GitHub style I wanted.

## Consequences

**Positive:**

- Ready-made, accessible components (keyboard navigation, focus handling, screen reader labels)
- Light and dark mode work out of the box via `data-color-mode="auto"`
- The app looks consistent without much custom CSS

**Negative / Trade-offs:**

- Bound to Primer's API and release cycle; some components are still experimental (e.g. `Blankslate`)
  or get deprecated (e.g. `Flash` → `Banner`)
- Larger bundle than plain CSS
- Less CSS practice than writing everything myself
