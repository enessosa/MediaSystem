# ADR-008: Open Registration Without Codeword, First User Becomes Admin

## Status

Accepted

## Date

21.10.2026

## Context

The original signup rule: the first 10 users register freely, from the 11th user on an admin-defined codeword
is required (wrong or missing codeword → registration rejected). Two problems showed up after deciding against
public hosting (ADR-007):

- There was no way to become admin except an SQL update in the database. Without an admin no codeword can be
  set, and without a codeword the 11th registration failed with a server error.
- For a private instance with a few users the codeword is mostly unnecessary.

Removing the codeword completely was considered, but it is the reason the admin role exists (single-table
inheritance `Admin extends User`, role-based authorization, `@PreAuthorize` as defense in depth), which is one
of the more interesting parts of the project.

## Decision

- The **first** registered user automatically becomes admin.
- If **no** codeword is set, registration stays open, also after the 10th user. If a codeword is set, it is
  required from the 11th user on as before.
- Admins can view, change and remove the codeword on the account page (`GET`/`PUT`/`DELETE /admin/codeword`).
- The last remaining admin can't delete their own account, so an instance never ends up without an admin.

## Alternatives Considered

- **Option A:** Remove the codeword and the admin role entirely: less code, but loses the role-based
  authorization part and requires reworking tested code and the planning documents.
- **Option B:** Keep the rule and make someone admin via SQL (documented in the README): no code change, but
  every new instance needs a manual database step.
- **Option C:** Without a codeword, close registration from the 11th user on: safer, but for a private
  instance it only blocks people who were invited anyway.

## Consequences

**Positive:**

- A new instance works without any manual database step
- The admin role and the codeword feature stay, but don't get in the way of private use
- No more server error when no codeword is configured

**Negative / Trade-offs:**

- If an instance is reachable before its owner registers, a stranger could become admin; the README says to
  register right after the first start
- Additional admins still have to be created via SQL; there is no UI for managing roles
