# ADR-009: nginx as Reverse Proxy, Frontend and API on One Origin

## Status

Accepted

## Date

23.10.2026

## Context

Phase 6 packages MediaSystem with Docker so that `docker compose up` starts the whole system (ADR-007: local or
private deployment only). In development, the frontend (Vite, `localhost:5173`) and the backend
(`localhost:8080`) run on two different origins. This only works because the backend allows exactly
`http://localhost:5173` via CORS, hard-coded in `SecurityConfig`, and because the frontend sends the session and
CSRF cookies with every cross-origin request (`credentials: 'include'`).

In the containers, the frontend is no longer served by Vite but as static files after `npm run build`. Something
has to serve those files, and the browser has to reach the API. Keeping two origins would mean making the CORS
origin configurable and dealing with cross-origin cookies on every deployment. A reverse proxy was planned for
Phase 6 anyway, but the choice between nginx and traefik was still open.

## Decision

nginx runs as the only container reachable from outside. It serves the built frontend files and forwards every
request under `/api/` to the backend container, removing the `/api` prefix, so the backend's routes stay
unchanged. The browser sees a single origin, so CORS is no longer needed and cookies work without special rules.
Backend and Postgres are only reachable inside the Docker network. nginx also falls back to `index.html` for
unknown paths, so client-side routes (e.g. a reload on `/entries/5`) keep working. HTTPS, if needed for a private
server, is added at the same place later.

## Alternatives Considered

- **Option A:** Keep two origins and make the CORS origin configurable via an environment variable: smallest
  change, but cross-origin cookies stay a source of errors, and a separate server for the frontend files is still
  needed.
- **Option B:** Bundle the frontend into the Spring Boot jar (`static/` folder): a single container and one
  origin without a proxy, but frontend and backend builds get coupled, and the reverse proxy part of Phase 6 is
  skipped.
- **Option C:** traefik instead of nginx: discovers containers automatically and fetches Let's Encrypt
  certificates, but both mainly pay off for public hosting with real domains, which ADR-007 rules out. nginx needs
  one small config file in which every line can be understood.

## Consequences

**Positive:**

- One origin: no CORS configuration, no cross-origin cookie issues
- Only one open port; backend and database are not reachable from outside
- The reverse proxy from the Phase 6 plan is in place, and HTTPS can be added there later

**Negative / Trade-offs:**

- One more container and one more config file to maintain
- Development (Vite + `localhost:8080`) and the Docker setup use different paths to the API (`VITE_API_BASE_URL`),
  so the CORS rule for the dev server stays in the code for now
- The `/api` prefix exists only in nginx; a request that bypasses the proxy uses different paths
